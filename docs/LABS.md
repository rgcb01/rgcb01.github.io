# Interactive Labs

Interactive Labs is the educational section of the site: simulations of optics, semiconductors, mathematics, physics and engineering. Each lab ships with:

- its own shareable URL, `/labs/<slug>`. The simulation state is kept in the query string, so a specific setup can be shared too.
- an interactive simulation driven by one pure model,
- a mathematical explanation,
- scientific references,
- documented model limitations,
- optionally, a SimuLab guided explainer, plus short videos and publication images for LinkedIn and X.

The section uses the Portfolio 2.0 design (`.pro-site` tokens). Lab styles are scoped to `.lab-*` and `.card` in `src/labs.css`.

## Routes

| Route | What | Source |
|---|---|---|
| `/labs` | index with domain filter | `src/components/labs/LabsIndex.jsx` |
| `/labs/<slug>` | lab page (lazy-loaded with KaTeX) | `src/components/labs/LabPage.jsx` |
| `/labs/<slug>/card?format=…` | publication card, `noindex`, for capture only | `src/components/labs/LabShareCard.jsx` |
| `/` section 06 | newest labs teaser | `src/components/labs/LabsTeaser.jsx` |

`scripts/copy-404.mjs` writes real HTML for `/labs` and every published lab. Each page gets its own title, description, canonical URL, Open Graph image and alt text, and `LearningResource` or `CollectionPage` structured data, so link previews work without JavaScript.

## Anatomy of a lab

```
src/labs/registry.js                 one entry per lab (metadata, status, image paths, lazy loaders)
src/labs/<slug>/model.js             pure physics/maths: no DOM, no imports; every number comes from here
src/labs/<slug>/content.js           mathSections, limitations, references (plain data)
src/labs/<slug>/Lab.jsx              exports Simulation and ShareFigure
src/labs/<slug>/figures.jsx          SVG figures (optional split)
src/labs/<slug>/simulab/             optional SimuLab explainer: demo.json, demo.js, asset files, optional prepare.mjs
src/labs/<slug>/posts.js             optional post drafts for LinkedIn and X (otherwise a generic template is used)
src/labs/<slug>/published.json       optional frozen numbers used by video, cards and posts (verified by a check script)
scripts/labs/check-<name>.mjs        closed-form checks of the model (run by labs:validate)
public/assets/labs/<slug>/og.png     generated by labs:publish (committed)
public/assets/labs/<slug>/explainer.html  generated by labs:explainer (committed)
```

Rules the validator enforces (`npm run labs:validate`):

- kebab-case unique slug (it is the URL), unique number, known domains, ISO dates;
- `page` copy for the shared lab page (section titles, explainer text, reproduce text and the check commands, which must exist);
- a `model.js`, at least one math section, at least three limitations, and at least two references, each with a DOI or URL;
- `Lab.jsx` exports `Simulation` and `ShareFigure`;
- published labs have their `og.png`, and their explainer if one is declared;
- every `scripts/labs/check-*.mjs` passes;
- with `--dist` (after `npm run build`): each lab route has canonical, Open Graph and structured data.

The GitHub Pages workflow runs both checks before and after the build.

## Add a lab

1. Write `src/labs/<slug>/model.js`: pure functions and constants. Use only top-level `export const` / `export function` and no imports, so SimuLab can reuse the file.
2. Add `scripts/labs/check-<slug>.mjs`, which compares the model with values you can derive by hand. Show one of those checks on the page (`check` in a math section).
3. Write `content.js`. Verify every reference before citing it. If a DOI cannot be confirmed, cite the archive URL instead of guessing one.
4. Build `Lab.jsx` with `Simulation` (read and write the URL query for shareable states) and `ShareFigure` (fixed-pixel figure for the cards).
5. Add the registry entry with `status: 'draft'` while working. Switch it to `'published'` when ready.
6. Run `npm run labs:publish -- <slug>` to produce `og.png`, then `npm run build && npm run labs:validate`.

## SimuLab explainer, video and publication assets

SimuLab is vendored at `.claude/skills/simulab/` (MIT, see its `UPSTREAM.md` for the two local fixes). Claude Code loads it as a project skill.

```bash
npm run labs:setup                                      # once: skill npm deps + numpy/scipy (ffmpeg must be on PATH)
npm run labs:explainer -- <slug> build                  # -> public/assets/labs/<slug>/explainer.html
npm run labs:explainer -- <slug> stills 3 9 15 21 27    # -> exports/labs/<slug>/stills.jpg (review frames)
npm run labs:publish -- <slug>                          # og.png + LinkedIn/X images + post.md drafts
npm run labs:publish -- <slug> --video --preview        # + 750 px / 30 fps videos (fast check)
npm run labs:publish -- <slug> --video                  # + final 1500 px / 60 fps master and social cuts
npm run labs:publish -- index                           # /labs Open Graph image
```

`labs:publish` builds the site, serves it with `vite preview`, and captures the card route at exact sizes:

| File | Size | Use |
|---|---|---|
| `public/assets/labs/<slug>/og.png` | 1200 × 630 | link previews (committed) |
| `exports/labs/<slug>/<slug>-linkedin.png` | 1080 × 1350 | LinkedIn image post |
| `exports/labs/<slug>/<slug>-x.png` | 1600 × 900 | X image post |
| `exports/labs/<slug>/<slug>.mp4` | 1500 × 1200, 60 fps | master explainer video, −14 LUFS |
| `exports/labs/<slug>/<slug>-linkedin-1080x1350.mp4` | 1080 × 1350, 30 fps | LinkedIn native video |
| `exports/labs/<slug>/<slug>-x-1920x1080.mp4` | 1920 × 1080, 30 fps | X native video |
| `exports/labs/<slug>/post.md` | — | draft post text to edit |

`exports/` is git-ignored: regenerate rather than commit videos.

When the explainer needs heavy computation (Lab 002 runs a 2D imaging model per frame state), `demo.json` can name a `prepare` module. `simulab.mjs` runs it before bundling, with the staging folder, and it writes generated data next to the scene files. Lab 002's `prepare.mjs` runs `model.js` once and packs 21 exact OPC-strength states (masks, aerial-image terrain, contours, per-site EPE) as base64 typed arrays.

How the explainer reuses the model: `scripts/labs/simulab.mjs` stages `src/labs/<slug>/simulab/` into `exports/.simulab/<slug>/`. There it wraps `model.js` into `model.gen.js` (a classic script exposing a global, `ORL` by default, or `modelGlobal` in `demo.json`), then runs the skill's `build`, `stills`, `record` (`--lang=en`), `audio` and `master` tools. The explainer text is written in English. `?lang=en` translates the kit's built-in labels, such as "THE BIG IDEA".

When reviewing an explainer, follow the skill's checklist on stills, never from memory. Check that nothing overlaps, that panels agree with the picture, and that each state holds long enough to read.

## Lab 002: verified numbers

`src/labs/optical-proximity-correction/published.json` holds every number quoted outside the live simulation: the video, cards and post drafts. `node scripts/labs/check-opc-published.mjs` recomputes them from `model.js`, and also compares them with the numbers embedded in the committed explainer. After any model change, run `--write` and re-render: `npm run labs:explainer -- optical-proximity-correction build`, then `npm run labs:publish -- optical-proximity-correction --video`.

`node scripts/labs/check-opc-model.mjs [--report]` is the validation suite:

- physical sanity: clear field, the ¼ coherent edge intensity, symmetry;
- FFT-grid convergence from 128 to 512 points;
- bicubic versus exact spectral intensity, and sub-pixel EPE against an analytic edge;
- drawn-contour accuracy;
- Vogel-spiral illumination convergence against 1000 points;
- OPC at independent evaluation sites;
- the pitch study where the simple feedback loop stops converging.

## Lab 003: verified numbers and definitions

`src/labs/sub-resolution-assist-features/published.json` holds every number quoted outside the live simulation (video, cards, posts, the challenge reference). `node scripts/labs/check-sraf-published.mjs` recomputes it from `model.js` and compares it with the `summary` embedded in the committed explainer; `--write` regenerates it. The explainer's `prepare.mjs` packs 13 exact assist-width states (0 to 60 nm in 5 nm steps) with their through-focus intensity and full window analysis; only the drawing is interpolated between steps.

Definitions used throughout Lab 003:

- dose E in units of the dose to clear; threshold t = 1/E; printed = blurred intensity below t (bright-field mask, positive resist);
- EL = (E_b − E_a) / E_mid; DOF at 5 % EL by the exposure-defocus method (Lin 1994);
- three nested windows: CD-only (main line within ±10 %), defect-free (also nothing else prints), safe (every unwanted dip at least 10 % above threshold, an educational heuristic);
- NILS on the aerial image at x = CD/2; the blurred-image value is also reported.

`node scripts/labs/check-sraf-model.mjs [--report]` is the validation suite:

- dose and EL definitions;
- exact ±z defocus symmetry and an exact two-beam image;
- analytic contour, NILS and print-onset tests;
- a synthetic process window with a closed-form DOF;
- grid, field, source, focus-step and dose-grid convergence;
- a point-by-point recheck that nothing prints inside the accepted windows;
- cross-checks against the Lab 001 and Lab 002 imaging models.

## Writing standards

- Every number on screen comes from the lab's model, including the video and the cards.
- Separate textbook physics from heuristics, and label heuristics as such (for example, printability thresholds).
- Presets are "typical public values", never a specific tool or process. Do not use employer or proprietary data.
- Own-design drawings only. No third-party logos or brand look-alikes.
